# Sam v0.7.0: Immutable Collections & Bounded Concurrency (DRAFT)

*Draft document for implementing v0.7.0 features. See `analysis_v0.7.0.md` and `PROPOSAL_v0.7.0.md` for full details.*

## Overview

This document outlines the design for Sam v0.7.0, adding:
1. **Immutable collections via `yield`** in `for` loops
2. **Bounded concurrency** with ordered/unordered result preservation

---

## Syntax

### For loop with concurrency modifier

```sam
// Ordered by default - preserves original iterable order
let summaries = for part in chunks with { parallel: 3 } {
  let res = use Summarizer<Summary>(part)
  if (!res.ok) { return res }
  yield res.value
}

// Unordered - results may complete in any order
let summaries = for part in chunks with { parallel: 3, ordered: false } {
  yield res.value
}

// Sequential (no with block - backward compatible)
let results = for item in data {
  yield transform(item)
}
```

### `yield` expression

```sam
// Collect values into immutable array
let results = for item in data {
  yield transform(item)
}

// Filter with continue
let results = for item in data {
  if (shouldSkip(item)) { continue }
  yield item
}

// Abort flow + cancel parallel tasks
let results = for item in data with { parallel: 4 } {
  let res = use Processor(item)
  if (!res.ok) { return res }
  yield res.value
}
```

### `parallel` heterogeneous fan-out (already works)

```sam
let { sec, perf } = parallel {
  sec: use Auditor<SecurityReport>(diff),
  perf: use Auditor<PerformanceReport>(diff)
}
```

## AST Changes

### `ForStatementNode` extended (`packages/compiler/src/parser/ast.ts`)

```typescript
export interface ForStatementNode {
  type: "ForStatement";
  iterator: string;
  iterable: ExpressionNode;
  parallel?: number;      // Optional concurrency limit (>0)
  ordered?: boolean;      // Optional order preservation (default: true)
  body: StatementNode[];
}
```

### `YieldExpression` added to `ExpressionNode`

```typescript
| { type: "YieldExpression"; value: ExpressionNode; }
```

---

## Parser Changes (`packages/compiler/src/parser/parsers/flow/parseStatement.ts`)

- Modify `parseForStatement` to optionally parse `WITH LBRACE ... RBRACE` block
- Add `parseYieldStatement` to recognize `YIELD` keyword and parse following expression

---

## Validator Changes (`packages/compiler/src/parser/validator.ts`)

- Validate `parallel` is positive integer if present
- Validate `ordered` is boolean if present; cannot be `true` without `parallel`
- **`break` enforcement**: 
  - Sequential `for`: allowed (stops loop, preserves collected items)
  - Parallel `for`: **semantic error** (throws error)
- Track `return` to cancel pending parallel tasks

---

## Codegen Changes (`packages/compiler/src/codegen/generators/flow/generateFlow.ts`)

- Branch based on `statement.parallel`:
  - **Sequential**: Existing `for...of` generation
  - **Parallel**: Generate concurrent execution with ordered/unordered result collection
- Transform `yield <expr>` → `results[idx] = <expr>` (when `ordered: true`) or `results.push(<expr>)` (when `ordered: false`)
- Safe template literal interpolation: auto-`JSON.stringify()` array interpolations

---

## Template Literal Safe Interpolation

**Problem**: `` `Resumen: ${summaries}` `` where `summaries` is `Summary[]` produces `[object Object]`.

**Solution**: In codegen's `generateExpression` for `TemplateLiteral`, auto-detect array expressions and wrap with `JSON.stringify()`.

## Backward Compatibility

- Existing `for ... in ... { }` works without `with` block (sequential, ordered by default)
- `parallel { ... }` heterogeneous fan-out already works unchanged
- All 127 existing tests pass without modification

---

## Open Questions

1. **`with` as keyword**: Need to add `WITH` token type or recognize in for-context only
2. **`yield` as statement vs expression**: Chosen as statement (has effect of adding to results)
3. **Index tracking for ordered results**: Codegen must track original index of each iteration
4. **`return` cancellation in parallel**: At codegen level (generated JS uses cancellation flags)
5. **`break` in parallel**: Explicitly forbidden with clear error message
